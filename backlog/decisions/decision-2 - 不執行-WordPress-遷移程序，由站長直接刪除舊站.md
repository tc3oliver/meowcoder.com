## Context

PRD（`doc-1`）§31 規定一套完整的 WordPress 遷移程序：匯出現有 URL、標題、文章、有價值媒體、外部連結與已索引頁面清單；保留資料庫與 `wp-content/uploads` 的私有備份；並依政策建立轉址對應（有對應 Study 文章者 301 至 Study、舊 About 與首頁 301 至新頁面、無替代內容者回應 410 Gone），且明確禁止把所有舊 URL 一律轉址至 `/`。§38 第 17 點要求 WordPress 正式環境介面完全移除。這套需求原本由 MCD-12（TASK-12）承接，並作為 MCD-13 的前置。

規劃完成後，站長明確表示會自行直接刪除既有 WordPress 站台，不需要本專案處理；並會在之後自行將 `meowcoder.com` 網域轉指到新站。

## Decision

不執行 PRD §31 的遷移程序。放棄 URL 盤點、私有備份與 301/410 轉址對應，MCD-12（TASK-12）自 backlog 移除（archive，非刪除，以保留紀錄）。MCD-13 保留 DNS 與 TLS 切換，因為網域仍會轉指到新站；並保留「正式環境不得存在 WordPress 執行介面」的確認，該項同時由 PRD §32 要求，成本極低。

## Consequences

- 舊 WordPress URL 在切換後會回應 404 而非 301 或 410。既有搜尋排名、已索引頁面與外部連結（backlinks）的權重不會傳遞到新站，需視為已接受的損失。
- 不保留 PRD §31 要求的私有備份，因此本次切換沒有回滾路徑。若刪除後才發現仍需舊內容（例如某篇文章尚未遷移到 Study），將無法復原。備份與否由站長自行決定，不屬本專案範圍。
- TASK-13 的依賴由 `TASK-3, TASK-11, TASK-12` 縮減為 `TASK-3, TASK-11`，並移除轉址部署、轉址抽樣驗證與以備份為回滾依據的相關驗收。
- PRD §31 與 §38 第 17 點在本次實作中被本決策部分推翻；`doc-1` 維持原文不動，需求差異以本決策記錄追溯。
- 若日後改變主意要保留轉址，推翻此決策需建立新的決策記錄，而不是修改本記錄。
