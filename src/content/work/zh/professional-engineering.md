## 這一頁涵蓋什麼

這十多年的工程經驗都是在組織內部完成的，因此在這裡以一段整體敘事呈現，而不是逐一列出專案：它們無法對外連結，也不會被指名。這些系統為誰而建、內部叫什麼名字，全站都不會出現。

去掉那些之後，剩下的仍然是實質的部分：問題領域、工程職責與技術範圍，以概括的方式描述，並歸納為反覆出現的三個主題。以下不宣稱任何成效，因為沒有人能查證的成效不是證據，只是一種說法；這一頁是打算在沒有那種說法的情況下，仍然值得一讀。

## AI 系統應用

<p class="theme-domains">對話式系統 · 會議智能 · 知識取用 · 自然語言 BI · 電腦視覺</p>

最近幾年的工作是 AI 系統的實際應用。實務上這意味著：模型只是系統裡的其中一個元件。模型負責的是無法用人工寫死的那一段，而它周圍的一切——檢索、身分驗證、記錄、並行處理，以及使用者真正接觸到的那層介面——都是尋常的工程，而且是工作量的大宗。

其中一條線是會議智能：對錄下的討論做語音辨識，為產出的逐字稿做摘要，區分不同發言者，從談話內容整理出待辦事項，對累積下來的會議記錄做檢索增強問答，並在中英文之間翻譯文件。它以網頁前端與 API 一併交付，因此如何承接多人同時使用，和模型本身一樣屬於設計的一部分。

第二條線是客服場景的對話系統：理解進來的問題、查詢常見問答與知識庫、以多輪對話維持前後文，並用嵌入向量搭配近似最近鄰檢索，讓一個和答案沒有共同關鍵字的問題仍然找得到答案。這類系統會把對話交還給真人，而不是假裝不需要真人；於是交接的邊界、交接前後的記錄，以及模型表現隨時間的監控，都被放進設計裡，而不是事後補上。

第三條線是與商業資料的互動：把自然語言提出的問題轉成 SQL，產生回答這個問題的圖表或報表，並在底下把多個來源整合進資料倉儲，讓查詢有一個一致的對象——同時要有權限控管與快取，因為一個誰都能問的問題，也是一個誰都能跑的查詢。

三條線底下還有比較安靜的另一半：意圖建模、語料蒐集與標註，以及多輪對話流程設計。電腦視覺也是從同樣的角度進來的，用在隱私保護而不是辨識本身——以人臉偵測自動模糊與遮蔽，讓錄下的素材可以保留，而不必連每個人的臉一起保留。

## 企業與雲端系統

<p class="theme-domains">後端服務 · 雲端基礎架構 · 身分與權限控管 · 即時通訊 · 企業工作流程 · 正式環境維運</p>

在 AI 成為工作重心之前——而且到現在仍然墊在底下——是企業系統工程：有真實使用者、有稽核軌跡，也有一條必須待在裡面的法遵邊界。

資訊安全治理是其中一種形態：單一登入與權限控管、弱點掃描與風險評估、把簽核流程從紙本搬進系統，以及把缺失追蹤到結案，整體對齊 ISO 27001 的實務要求。追蹤與簽核類系統則是另一種：先做需求分析與資料建模，接著是微服務架構，再往上疊查詢與報表，給那些得為流程負責的人使用。

即時通訊是從遠距醫療進來的——以 WebRTC 進行參與者之間的即時視訊、原生行動應用程式搭配管理平台，以及錄影，連同錄影本身所要求的安全控管。同一時期的其他系統則屬於工作流程而非即時類型：申請與通報流程、行動平台與雲端儲存應用。

真正能跨越個別系統的，是工程實務本身。版本控管與 CI/CD 規範、以程式碼定義基礎架構、靜態分析與相依套件檢查、開發範本與文件——以及把這些在內部教出去，連同 API 設計、身分驗證與授權、發布與維運、服務拆分、容器化與部署。近幾年這同時也是工程管理的責任，而那件事大致上是讓規範成為比較好走的那條路，而不是被要求走的那條。

## 行動與連網產品

<p class="theme-domains">iOS 與 Android · 零售與後台系統 · 連網裝置與智慧家庭 · 室內定位 · 網頁與 API 整合</p>

墊在上面兩者底下的基礎更早，範圍也更窄：就是應用程式，問題需要哪個平台就寫哪個平台。

起點是 iOS 的接案與外包工作，之後擴大為雙平台行動開發，再往這些應用程式背後的系統延伸——零售與後台營運的 POS 與 ERP、網頁系統、雲端服務，以及把它們彼此接起來的 API 整合。

連網裝置是另外一半。智慧家庭雲端平台意味著裝置註冊與管理、從不只一種端點進行控制、把人物與人臉辨識用在門禁與門鈴情境，以及一套自動化規則引擎——離家模式、節能，還有一個家實際上會需要的那些條件判斷——部署時考慮高可用性，設計時考慮安全存取。藍牙低功耗的室內定位與位置追蹤又是另一門學問：一個從來不夠可靠的訊號，要變成一個仍然堪用的位置。

這段時期用過的語言是平台要求什麼就用什麼——C++、C#、Objective-C、Swift、JavaScript、Dart、Python。真正延續下來的，不是其中任何一個。

## 職涯進程

十一年，四個階段：起初是行動應用的接案與外包，接著是軟體工程，再到資深與技術主管工作，近期則是 AI 工程與工程管理並行。若只看技術的形狀，可以說得更短。
